# 집사 (Zipsa) 🐱

윈도우에서 깨지지 않는 ZIP을 만드는 macOS용 압축 도구입니다.
맥이 흘리고 다니는 털(`.DS_Store`, `._*`)을 치우고, 흐트러진 한글 자모를 단정하게 정리해 드립니다.

- **macOS 전용 파일 제외**: `.DS_Store`, `._*`, `__MACOSX`, `.Spotlight-V100`, `.Trashes`, `Icon\r` 등. 확장 속성·리소스 포크도 넣지 않습니다.
- **한글 파일명 NFC 정규화**: ZIP 안의 모든 경로를 NFC로 바꾸고 UTF-8 플래그를 기록해서, 윈도우 탐색기·반디집·7-Zip 어디서 풀어도 자소 분리나 깨짐이 없습니다. 만들어지는 ZIP 파일 이름 자체도 NFC입니다.
- 원본 파일은 건드리지 않습니다. 4GB 넘는 파일도 됩니다(ZIP64).

## 설치

```bash
git clone https://github.com/dkjung7131-ctrl/zipsa.git
cd zipsa
bash install.sh
```

git이 없으면 이 페이지의 **Code → Download ZIP**으로 받아서 푼 뒤 `bash install.sh`를 실행하세요.

- 터미널 명령어 `~/.local/bin/zipsa`, 앱 `~/Applications/집사.app`, Finder 우클릭 메뉴가 설치됩니다.
- macOS 기본 `python3`와 `swiftc`(Xcode Command Line Tools)를 씁니다. 없으면 설치 창이 뜹니다.

## 사용법

**앱**: 파일이나 폴더를 `집사.app` 아이콘 위로 끌어다 놓으면 같은 폴더에 `이름.zip`이 생깁니다. Dock에 올려두면 편합니다.

**Finder 우클릭**: 항목을 선택하고 우클릭 → **집사에게 압축 맡기기**. 완료되면 알림이 뜹니다.
macOS가 처음에는 이 메뉴를 꺼 두기 때문에 **한 번만 켜 주세요**: 시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램 → (카테고리별) **파일 제공자** ⓘ → `집사` 켜기.
(집사.app 안에 들어 있는 Finder 확장입니다. 개발자 계정 없이 설치할 때 직접 빌드합니다.)

**터미널**:

```bash
zipsa 폴더                  # → 폴더.zip
zipsa a.pdf b.xlsx 폴더     # 여러 개 → Archive.zip
zipsa -o ~/Desktop/전달.zip 폴더
zipsa -l 9 폴더             # 압축 레벨 0~9 (기본 6)
```

파일 하나를 압축하면 윈도우처럼 확장자를 뺀 이름으로 만듭니다(`사진.jpeg` → `사진.zip`, 폴더는 이름 그대로).
같은 이름의 ZIP이 이미 있으면 Finder처럼 `이름 2.zip`으로 만듭니다(`-o`로 지정하면 덮어씀).

## 업데이트

압축할 때 하루 한 번 새 버전이 나왔는지 확인해서, 있으면 알림이나 터미널 메시지로 알려 줍니다. 설치는 직접 할 때만 합니다.

- **앱**: `집사.app`을 더블클릭 → **업데이트**
- **터미널**: `zipsa --update`

새 버전 확인은 GitHub 릴리스 페이지에 접속하는 것뿐이고, 파일 이름 같은 정보는 보내지 않습니다. 터미널에서 확인을 끄려면 `ZIPSA_NO_UPDATE_CHECK=1`을 설정하세요.
업데이트 뒤 데스크탑·문서 폴더 접근 권한을 다시 물어볼 수 있습니다.

## 참고

- 심볼릭 링크는 윈도우에서 제대로 풀리지 않아 건너뛰고, 결과 요약에 표시합니다.
- 1980년 이전 수정 날짜는 ZIP 형식 한계로 1980-01-01로 저장됩니다.
- 처음 실행할 때 데스크탑·문서 폴더 접근 권한을 물어보면 허용하세요.
- 아이콘 원본은 `icon.svg`입니다. 수정한 뒤 `install.sh`를 다시 실행하려면 `zipsa.icns`도 새로 만들어야 합니다.

## 새 버전 배포하기 (개발자용)

1. `zipsa.py`의 `VERSION`을 올립니다 (예: `1.2.0` → `1.2.1`).
2. 커밋하고 `git push`.
3. `bash release.sh` — GitHub 릴리스 `v1.2.1`을 만들고, 사용자는 하루 안에 업데이트 알림을 받습니다.

main에 push만 해서는 사용자에게 가지 않습니다. 릴리스를 만들어야 배포됩니다.
